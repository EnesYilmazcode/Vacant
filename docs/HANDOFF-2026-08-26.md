## The three findings that already changed the design

### 1. The harvest is 8x cheaper than planned

Finder walks 243 subjects, which costs roughly **1,142 requests** per term. The same
API paginates by `catalog-number` bucket, and **8 buckets cover all 26,298 sections
in 136 requests**, about 52 seconds, one pass, no reconciliation loop. Verified
lossless against the subject walk on the bucket where both were run.

Do not port Finder's subject discovery. Port its bucket sweep and stop there.

### 2. The README's size numbers were wrong in the expensive direction

| README claimed | Measured | Off by |
|---|---|---|
| "~100 KB gzipped" index | **27 to 54 KB gzipped** depending on room count | 2 to 3x |
| "1,200 to 1,800 rooms" | **1,067 rooms** | mildly high |
| "100 to 150 buildings" | **116 buildings** | close |

Note the correction to the correction. A sampling extrapolation first put this at
~625 rooms in ~88 buildings, which was too low. The figure above is a direct read
of Roomix's own published index for the same term, which is the strongest evidence
available. The README carries it.

### 3. The refusal guards must count busy blocks, not rooms

This is the important one. **A complete, healthy harvest already reports 81% of
campus as free** (measured Mon-Fri 08:00 to 22:00 in 30 minute steps over 290 rooms).
So "this room is free" is the default answer, and a harvest that silently loses busy
blocks does not look broken. It looks like good news.

A run that dropped 20% of its busy blocks would lose at most 18 rooms out of 290,
a 6.2% drop, which sails under Finder's 10% `MAX_DROP` and ships.

```
   Finder's failure                  Vacant's failure
   ----------------                  ----------------
   rows go missing                   busy blocks go missing
        |                                 |
        v                                 v
   the picker is short               the grid says "free"
        |                                 |
        v                                 v
   student notices a                 student walks to a locked room,
   course is absent                  or into someone's lecture
        |                                 |
        v                                 v
   ROOM COUNT catches it             ROOM COUNT DOES NOT CATCH IT
                                     block count does
```

`Finder/scripts/guards.mjs` is the right pattern and the wrong metric. Copy the file
byte for byte, then key Vacant's thresholds on busy blocks and busy minutes.
