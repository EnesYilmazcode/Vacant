# Non-class occupancy overlay (#110)

Updated 2026-09-04 after #114. The verified input is now the Registrar Room
Matrix snapshot generated by `scripts/fetch-room-events.mjs`, not the proposed
EMS/organization-feed contract from #113.

## Input

`scripts/lib/club-occupancy.mjs` consumes the parsed
`data/room-events-<term>.json` document directly. Its relevant shape is:

```json
{
  "_meta": {
    "term": "1268",
    "weekStart": "2026-08-31",
    "weekEnd": "2026-09-06",
    "source": "https://courses.erppub.osu.edu/...",
    "partial": false
  },
  "rooms": {
    "AA0005": [
      { "kind": "event", "day": 4, "start": 1080, "end": 1155,
        "type": "MTG", "eventId": "000657000" }
    ]
  }
}
```

The matrix weekday is converted to a date in the declared Monday-through-Sunday
week. Organization names are neither required nor reconstructed: #114 drops the
Registrar's free-text label because some labels identify a person. The type code
is enough to make the occupancy claim.

## Boundary rules

- The Room Matrix term must match the class index term when both are present.
- Room IDs must exist in the class index.
- Events require a valid weekday, minute range, nine-digit reservation ID and
  one of MTG, TOUR, INFO, WRKS, SMNR, RCPT, INTV or FAIR. RCPT, INTV and FAIR
  first appeared in the 09/07/2026 sweep and mean ordinary registered
  receptions, interviews and fairs, so they carry the same occupancy rule.
- Duplicate records for the same room, date, time and reservation ID collapse.
- Unknown fields are never copied into normalized output.
- `ROOM BLOCK` is counted and reported as `undecided-room-block`, never overlaid.
- Dates outside the snapshot return `outside-snapshot`, not an empty-calendar
  claim. A one-date session prevents a weekly recurrence from being invented.
- The original class index and its existing busy tuples remain unchanged.

`normalizeMeetings(roomEvents, { rooms, term })` returns dated event occurrences
plus explicit rejections and coverage metadata. `overlayForDate(index,
roomEvents, { date })` returns a copy of the class index with that date's events
added. The caller must parse the JSON before passing it; the module performs no
network or filesystem I/O.

Run the focused tests:

```sh
node --test scripts/test/club-occupancy.test.mjs
```

The final test reads the committed #114 snapshot and asserts that all 327 events
are accepted while all 347 ROOM BLOCK records are visible but excluded.

`data/current.json` names the term's event snapshot. Application boot fetches it
beside the class index, ranking queries the overlaid index for the current date,
and the room screen rebuilds it for every date selected in the calendar. Events
have no label in the privacy-reduced source, so the room grid renders them as
`In use`. Outside the swept week, the UI explicitly says that non-class event
coverage is unavailable. The weekly rooms workflow refreshes the Room Matrix
after rebuilding the class index and commits both together.
